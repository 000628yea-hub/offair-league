## 만든 것 (순서대로)

1. **우리 호스트 대시보드** — 소속 호스트 진단(효율·해외비율·노출 기반), 졸업 트래커, 신규 크리에이터 분석, 구간별(A1 상위권 vs 우리) 비교, 에이전시 액션. 백스테이지 데이터 기반.
2. **디자인 전면 개편** — OFF-AIR 브랜드 덱 기준 흑백 에디토리얼(빨강 1색만 경고용), Archivo+Pretendard+IBM Plex Mono.
3. **결과 패널 단순화** — "컷인지 조각인지"만 바로 보이게, 컷 데이터 직접입력 UI 제거.
4. **GitHub Pages 정식 배포** — repo 생성, push, Actions 워크플로우, Pages 설정.
5. **데이터 자동 수집 파이프라인**:
   - `collect.js`: tikple(리그 랭킹·컷 폴백·호스트 상세·사진) — 로그인 불필요, 매시간 자동.
   - **틱두(tikdo.kr) 실시간 컷**: 로그인 필요 + Vercel 봇 차단으로 서버(GitHub Actions/Cloudflare Worker)에서 직접 호출 불가 → **브라우저 유저스크립트**로 해결.
   - **백스테이지 "우리 호스트" 데이터**: 마찬가지로 로그인 필요 → **브라우저 유저스크립트**로 자동화(페이지당 100개로 늘려 자동 페이지네이션 후 GitHub에 커밋).

## 핵심 메커니즘: 브라우저 유저스크립트 2개

로그인이 필요한 두 데이터 소스(tikdo, LIVE Backstage)는 서버에서 못 긁어오므로,
**관리자가 그 페이지를 열 때 자동으로 데이터를 GitHub에 커밋**하는 방식을 씀.

| 유저스크립트 | 여는 페이지 | 채우는 데이터 | 파일 |
|---|---|---|---|
| `tikdo-userscript.user.js` | tikdo.kr/league/cutoffs | 리그별 실시간 조각컷 | `tikdo-cuts.json` (repo 루트) |
| `backstage-userscript.user.js` | live-backstage.tiktok.com 크리에이터 데이터 | 우리 호스트 진단 전체 | `backstage-creator-data.json` (repo 루트) |

- 설치: Tampermonkey 확장 + 각 스크립트 설치 + GitHub Fine-grained 토큰(Contents R/W, `offair-league` repo 전용, No expiration) 1개를 두 스크립트에 공용으로 사용.
- 자세한 설치 절차: [`scripts/README.md`](../scripts/README.md)
- 동작 조건: 관리자가 그 페이지를 **하루 한 번이라도 열어야** 그날치가 반영됨. 안 열면 이전 값 유지(72시간 지나면 틱플 폴백 값으로 자동 전환, 컷의 경우).
- 로그아웃하면 안 됨 — 로그인 세션이 있어야 스크립트가 데이터를 읽을 수 있음.

## 시행착오 (참고용)

- Cloudflare Worker로 tikdo API 프록시 시도 → tikdo가 Vercel 호스팅이라 **Vercel Security Checkpoint**(봇 체크)가 데이터센터 IP를 전부 차단해서 실패. 최종적으로 유저스크립트 방식으로 전환.
- GitHub 인증(Git Credential Manager) 관련 시행착오 — 최종적으로 브라우저 팝업으로 로그인 완료, 이후 세션에서는 직접 push 가능.
- 데이터 경로 설계: `data/` 폴더는 GitHub Actions 캐시가 매 실행 덮어써서, 유저스크립트가 커밋하는 파일은 **repo 루트**에 두고 배포 시점에 `_site/data/`로 복사하는 방식으로 캐시 충돌 회피.
